# Design Systems and Component Documentation

## Goal
Create a small, usable component library with shared tokens and documented states.

## Key concepts
- Tokens capture decisions that should remain consistent.
- Components need usage guidance and state coverage.
- Document do/don't examples and accessibility expectations.
- A design system should reduce inconsistency without blocking legitimate variation.


## Run the lesson
Open `index.html` in your browser. For a more realistic workflow, use VS Code Live Server.

## Files
- `index.html`: semantic structure and sample content
- `styles.css`: visual system and responsive behaviour


## Practice
Complete `exercises.md`. Test keyboard navigation and resize the browser before calling the lesson complete.

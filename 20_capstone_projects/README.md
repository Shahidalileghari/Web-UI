# Advanced Web UI Capstone Projects

Build each project as a front-end-only experience first. Use mock data and clear documentation; do not imply that a front-end-only demo provides real authentication, payments, or backend persistence.

## 1. SaaS Analytics Dashboard
- Responsive app shell, navigation, metrics, filterable data table, charts or chart placeholders.
- Include loading, empty, error, and populated states.
- Support keyboard navigation and narrow screens.

## 2. E-commerce Storefront UI
- Product grid, category filters, sorting, product detail view, cart drawer/page.
- Use local mock data; clearly label any browser-only cart persistence as a demo.
- Include empty-cart and out-of-stock states.

## 3. Editorial Tech Blog
- Responsive article list, topic tags, search, article typography, contents navigation.
- Add dark theme with a preference toggle and reduced-motion support.
- Optimize long-form readability and heading structure.

## 4. Component Design System
- Buttons, links, badges, cards, text fields, selects, dialogs, tabs, alerts, and progress.
- Document default, hover, focus, disabled, loading, error, and empty states as relevant.
- Include design tokens and usage guidance.

## 5. Accessible Portfolio Website
- Home, About, Skills, Projects, Experience, Contact.
- Mobile-first layout, accessible navigation, project filtering, contact form validation.
- Avoid fake claims; form submission requires a real service/backend to deliver messages.

## Delivery checklist
- [ ] README with goals, setup, and limitations
- [ ] Semantic HTML and logical heading structure
- [ ] Responsive checks at 320px, 768px, and desktop
- [ ] Keyboard-only test and visible focus
- [ ] Reduced-motion support where motion exists
- [ ] Loading, empty, error, and success states where relevant
- [ ] Safe DOM handling for user-controlled text
- [ ] No secrets or private API keys in client-side files
- [ ] Browser console checked
- [ ] Screenshot review and known-issues list

# UI Architecture and Reusable Patterns

## Goal
Separate content, visual styles, and interaction so a UI remains understandable as it grows.

## Key concepts
- Reuse patterns, not abstractions for their own sake.
- Prefer explicit class names and predictable component boundaries.
- Design consistent states: default, hover, focus, disabled, loading, error, and empty.
- Keep markup semantic and styling local enough to reason about.


## Run the lesson
Open `index.html` in your browser. For a more realistic workflow, use VS Code Live Server.

- `styles.css`: visual system and responsive behaviour
